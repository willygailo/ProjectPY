S1SHELL - PROJECT PROMPT
Open-source CLI toolkit for Kali Linux: CVE research, scoped target profiling,
passive fingerprinting, and reporting for authorized security assessments.

======================================================================
1. PURPOSE
======================================================================

Build "S1shell", a Python CLI toolkit for security professionals and students to:

- Research and triage CVEs affecting a known software stack (public intel only;
  zero target contact)
- Profile explicitly authorized targets (URL, domain, IPv4, IPv6) for DNS
  records, HTTP/TLS protocol posture, and defensive security headers
- Passively identify server/CDN/WAF software from a single ordinary response
- Maintain an auditable record of scope, authorizations, and network actions
- Compile reproducible Markdown, JSON, and self-contained HTML reports


======================================================================
2. HARD RULES (apply to every feature and every line of code)
======================================================================

1. SCOPE FIRST (Fail-Closed).
   No packet is sent to a target unless the target resolves and matches an
   unexpired entry in the operator's scope file. Scope evaluation ALWAYS runs
   before authorization prompting or any target connection.

2. EXPLICIT AUTHORIZATION CONFIRMATION.
   Every target-touching command requires either `--authorized` on the CLI or
   an explicit interactive confirmation at a TTY prompt. If `--authorized` is
   omitted and stdin is not a TTY, fail immediately with exit code 3.

3. READ-ONLY & NON-INVASIVE ON TARGETS.
   Target interaction is restricted to standard GET/HEAD/OPTIONS requests and
   standard TLS handshakes. Never send exploit payloads, fuzz strings, brute-
   force attempts, credentials, or malformed packets.

4. CONSERVATIVE DEFAULTS.
   - HTTP redirects disabled by default (`follow_redirects=False`; record any
     `Location` header without following it)
   - Target request concurrency fixed at 1
   - Default network timeout: 10.0s (connect + read)
   - Response body cap: 2 MiB max read per response
   - File permissions: `~/.s1shell/` created as `0700`; `scope.yaml` and
     `audit.log` created as `0600`


======================================================================
3. NON-GOALS (do not implement, including as plugins or flags)
======================================================================

- Exploit code, PoC execution, or vulnerability confirmation payloads
- Payload generation or active probing (SQLi/XSS/SSRF/LFI test strings)
- WAF bypass, firewall evasion, request smuggling, or User-Agent spoofing
- Rate-limit evasion, proxy rotation, or IP rotation
- Brute force, password spraying, credential testing, or directory/subdomain
  enumeration
- Port scanning or host discovery outside single-target scope checks
- Fuzzing or denial-of-service testing
- Any state-modifying request against a target (POST/PUT/PATCH/DELETE)

If a request asks for any item above, decline, explain why in one sentence,
and offer the closest defensive alternative. The README must state this policy.

4. MODULES
======================================================================

4.1 cve  (public vulnerability research; zero target contact)

Sources:
  - NVD REST API 2.0: https://services.nvd.nist.gov/rest/json/cves/2.0
    (CVSS v4.0/v3.1/v3.0/v2.0 scores, CPE matches, published/modified dates)
  - CVE.org CVE Services JSON API: https://cveawg.mitre.org/api/cve/<CVE-ID>
    (authoritative CNA descriptions, affected products, and references)

Commands:
  s1shell cve search --keyword "nginx 1.18" --min-cvss 7.0
  s1shell cve search --cpe "cpe:2.3:a:f5:nginx:1.18.0:*:*:*:*:*:*:*"
  s1shell cve get CVE-2021-23017
  s1shell cve cache clear

Filters & Options:
  - `--min-cvss FLOAT`, `--severity {LOW,MEDIUM,HIGH,CRITICAL}`
  - `--published-after YYYY-MM-DD`, `--published-before YYYY-MM-DD`
  - `--offline` (cache-only), `--refresh` (bypass cache read)

Caching & Rate Limiting:
  - SQLite cache at `~/.s1shell/cache.db` with configurable TTL (default: 24h)
  - Token-bucket rate limiter respecting NVD limits:
      * Without `NVD_API_KEY`: max 5 requests / 30s
      * With `NVD_API_KEY` env var: max 50 requests / 30s
  - Exponential backoff on HTTP 429/503 respecting `Retry-After`
  - Output: `table` (default), `json`, `md`


4.2 scope  (governs all target-touching modules)

Storage:
  - YAML file at `~/.s1shell/scope.yaml` (override via `--scope-file` or
    `S1SHELL_HOME` environment variable)
  - Entry schema: `id`, `target`, `type` (`domain` | `ip` | `cidr` | `url_prefix`),
    `include_subdomains` (bool, default `false`), `owner`, `auth_ref`,
    `created_at`, `expires_at` (ISO-8601 UTC date/datetime), `notes` (optional)

Commands:
  s1shell scope add example.com --include-subdomains --owner "ACME IT" \
    --ref "SOW-2026-014" --expires 2026-12-31
  s1shell scope list
  s1shell scope check https://app.example.com
  s1shell scope remove <id-or-target>
  s1shell scope expire [--prune]

Matching & Anti-Escape Rules:
  - Normalize case, trailing dots, IDN/punycode, ports, and canonical IPs
  - Expired entries NEVER match `scope check`
  - `scope expire` reports expired entries (`--prune` removes them cleanly)
  - At check time, resolve domain targets via DNS and verify:
      1) Hostname or URL prefix matches an active entry (subdomains match ONLY
         if `include_subdomains: true`), AND
      2) Every resolved IP is either non-private/non-loopback/non-link-local OR
         explicitly covered by an active `ip`/`cidr` scope entry (blocks DNS
         rebinding / internal SSRF resolution to 127.0.0.1, 169.254.169.254,
         or RFC1918 addresses), AND
      3) If `ip`/`cidr` entries exist for that scope context, resolved IPs match
  - Pin the validated IP for the target connection so DNS cannot shift between
    `scope.check()` and `httpx` / `ssl` connection


4.3 profile  (single-target, read-only)

Accepts: `http://...`, `https://...`, bare domain (defaults to `https://`),
         IPv4, IPv6 (bracketed or bare).

Checks (strictly single-target, no crawling):
  - DNS: A, AAAA, and CNAME records via `dnspython`
  - Protocol: HTTP/1.1 vs HTTP/2 via ALPN (`httpx` with `http2=True`); detects
    HTTP/3 advertisement strictly from `Alt-Svc` header (no QUIC traffic)
  - TLS (for HTTPS targets):
      * Default: 1 standard TLS handshake reporting negotiated protocol version,
        cipher suite, certificate verification status/error, subject, issuer,
        SAN list, `not_before`, `not_after`, and days remaining
      * Optional `--tls-versions`: bounded standard handshakes for TLS 1.0–1.3
        only to flag deprecated TLS 1.0/1.1 support (no SSLv2/SSLv3/downgrade attacks)
  - Headers & Cookies:
      * Evaluates `Strict-Transport-Security`, `Content-Security-Policy`,
        `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`,
        `Permissions-Policy`
      * Flags server/stack disclosure banners (`Server`, `X-Powered-By`,
        `X-AspNet-Version`, `Via`)
      * Inspects `Set-Cookie` attributes (`Secure`, `HttpOnly`, `SameSite`)
      * Records HTTP status and `Location` on `3xx` without following redirects

Budget: 1 HTTP request to the exact URL + 1 TLS handshake by default.

Command:
  s1shell profile https://app.example.com --authorized --format md

Output: `json`, `md`, or `table`.


4.4 fingerprint  (passive technology & CDN/WAF verification)

Identifies web server, CDN, WAF, or framework hints visible in a single normal
response (headers, cookie names, TLS issuer/CN) against a local declarative
signature catalog (`signatures.yaml`).

Modes:
  - Standalone (guarded by Scope + Auth gates; 1 GET request + 1 TLS handshake):
      s1shell fingerprint https://app.example.com --authorized --format json
  - Offline (zero network requests; consumes saved `profile` JSON artifact):
      s1shell fingerprint --from-profile profile.json --format md

Reports vendor, category, confidence (`high`/`medium`/`low`), and exact
matched evidence. Never sends probes to trigger WAF block pages.


4.5 report  (report compiler)

Combines canonical JSON outputs from `cve`, `profile`, and `fingerprint` into
a unified assessment report.

Command:
  s1shell report build --profile profile.json --fingerprint fp.json \
    --cve cves.json --operator "Jane Doe" --format html --out report.html

Formats: `md`, `json`, or a single self-contained `html` file (inline CSS, zero
external CDN resources).
Security: Jinja2 `autoescape=True` MUST be enabled so untrusted headers/banners
from a target cannot inject script into the HTML report.
Metadata recorded in every report: UTC timestamp, operator name, matched scope
entry (`target`, `owner`, `auth_ref`, `expires_at`), and `S1shell` version.


4.6 audit  (read-only audit log viewer)

Command:
  s1shell audit list [--limit 50]

Reads `~/.s1shell/audit.log` (JSON Lines, one object per line). Every network
attempt (allowed, blocked out-of-scope, unauthorized, or errored) appends one
line recording: `timestamp_utc`, `category` (`target` | `intel`), `command`,
`target`, `resolved_ips`, `scope_id`, `auth_ref`, `authorized_via`, `outcome`,
`exit_code`, `duration_ms`, and `error`.

5. ARCHITECTURE & DATA FLOW
======================================================================

5.1 Layered Design

  +------------------------------------------------------------------+
  | 1. CLI & Output Layer (`cli.py`, `output.py`, `config.py`)       |
  |    argparse routing, shared flags, Rich rendering, exit codes    |
  +------------------------------------------------------------------+
                                  |
         +------------------------+------------------------+
         | Target-Touching Path                            | Intel / Offline Path
         v                                                 v
  +----------------------------------+       +----------------------------+
  | 2. Policy Gate (`guard.py`)      |       | `cve/service.py`           |
  |    a. Parse & normalize target   |       | `fingerprint` (--from-prof)|
  |    b. `scope.py` check + DNS pin |       | `report/service.py`        |
  |       -> Exit 2 if out of scope  |       +----------------------------+
  |    c. Confirm `--authorized` or  |                     |
  |       TTY prompt -> Exit 3 if no |                     v
  |    d. Execute bounded action     |       +----------------------------+
  |    e. `audit.py` append JSONL    |       | `http.py` (NVD / CVE.org)  |
  +----------------------------------+       | + `cve/cache.py` (SQLite)  |
                  |                          +----------------------------+
                  v
  +----------------------------------+
  | 3. Target Modules                |
  |    `profile/` & `fingerprint/`   |
  |    (single request via `http.py` |
  |     pinned to validated IP)      |
  +----------------------------------+

5.2 Canonical Artifact Contracts (`models.py`)

Every JSON output includes `schema_version: "1.0"`, `tool_version`, and
`generated_at_utc`. `profile.json`, `fingerprint.json`, and `cve.json` share
typed dataclasses validated by `report/loader.py` before rendering.


======================================================================
6. CLI CONVENTIONS & EXIT CODES
======================================================================

Entry point:      s1shell <module> <command> [options]
Common options:   --format {table,json,md,html}  --out FILE
                  --verbose  --no-color  --authorized
                  --scope-file FILE  --home DIR
Exit codes:       0  success
                  1  general/runtime/validation/network error
                  2  target out of scope (or DNS failed / unsafe IP)
                  3  authorization not confirmed

7. TECHNICAL REQUIREMENTS
======================================================================

- Python 3.10+
- Minimal dependencies (prefer stdlib `argparse`, `sqlite3`, `ipaddress`, `ssl`):
    httpx[http2]    (HTTP/1.1 & ALPN HTTP/2; HTTP/3 detected via Alt-Svc)
    dnspython       (A, AAAA, CNAME DNS queries)
    cryptography    (X.509 certificate parsing, SANs, expiry)
    rich            (terminal tables & output)
    PyYAML          (scope.yaml and fingerprint signatures.yaml)
    jinja2          (autoescaped HTML and Markdown report templates)
- Packaging: `pyproject.toml` (PEP 621), installable via `pipx install .`
- Kali setup: `scripts/install-kali.sh` installs apt prerequisites
  (`python3`, `python3-venv`, `pipx`) and installs `s1shell` via `pipx`
- License: MIT or GPL-3.0 (choose one before v0.1.0)
- Quality: `ruff` (lint + format), full type hints (`mypy` clean)
- Tests: `pytest` — 100% offline; mock all external HTTP/DNS/API calls and use
  only localhost ephemeral servers where socket tests are needed
- User-Agent: `S1shell/<version> (authorized assessment; +<project URL>)`

10. ACCEPTANCE CRITERIA
======================================================================

- `profile` or `fingerprint` on an out-of-scope or expired target exits with
  code 2 and transmits zero packets to that target
- Domain scope entries resolving to un-scoped loopback/private/link-local IPs
  fail closed with exit code 2
- Any target command without `--authorized` (and without TTY confirmation, or
  when user declines) exits with code 3 and transmits zero packets
- HTTP redirects are never followed automatically
- Every network attempt writes one structured JSONL line to `audit.log`
- Generated HTML reports escape untrusted target headers/banners (`autoescape=True`)
  and contain zero external network links/scripts
- Full `pytest` suite, `ruff`, and `mypy` pass completely offline
- `README.md` contains the authorized-use notice and "What S1shell Does Not Do"
- No code path implements any item listed in Section 3
